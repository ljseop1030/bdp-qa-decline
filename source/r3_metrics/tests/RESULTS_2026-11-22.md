## 실행

`source/r3_metrics`에서 다음 명령을 사용했습니다. 실제 실행에는 새로운 ID를 지정합니다.

```bash
export R3_PYTHON=/usr/local/bin/python2.7
R3_RUN_ID="repo-check-$(date -u +%Y%m%dT%H%M%SZ)"
sha256sum -c SHA256SUMS.txt
python2.7 -m unittest discover -s tests -p 'test_*.py' -v
bash tests/smoke_test.sh --output /project/statistics/${R3_RUN_ID}-smoke
bash load/preflight_check.sh --site cs.stackexchange.com --run-id ${R3_RUN_ID}-trial
bash load/run_r3.sh --site cs.stackexchange.com --run-id ${R3_RUN_ID}-trial
```

10사이트 실행은 기본 Hive 모드에서 다음 10개의 `--site` 옵션을 함께 전달했습니다.

```bash
bash load/run_r3.sh --run-id ${R3_RUN_ID}-ready   --site craftcms.stackexchange.com --site cs.stackexchange.com   --site drupal.stackexchange.com --site emacs.stackexchange.com   --site gardening.stackexchange.com --site interpersonal.stackexchange.com   --site parenting.stackexchange.com --site pets.stackexchange.com   --site vi.stackexchange.com --site woodworking.stackexchange.com
```

HDFS 결과는 `/project/statistics/repo77-20261122T060701Z-ready/site_metrics_monthly`입니다.
기준값은 `tests/scope_reference_audit.json`에서 실행한 사이트만 선택해 14열 전체를 비교했습니다.
행·키·건수·NULL 위치는 일치해야 하며 비율은 절대 오차 1e-12를 허용했습니다.

## Hive·Impala 연결

`sql/register_serving.hql`의 테이블 이름만 고유한 외부 시험 테이블명으로 바꾸고,
`hdfs getconf -confKey fs.defaultFS`와 결과 namespace를 합쳐 `r3_serving_uri`로 전달했습니다.
등록 후 Impala INVALIDATE METADATA와 REFRESH를 실행했습니다.
두 엔진에서 7열 전체를 조회해 630행의 계산 결과와 비교했습니다.
시험 테이블은 DROP했고 Parquet 데이터와 R2 기존 서빙 테이블은 보존했습니다.

실제 VM에서 확인한 수정:

- Spark 1.3 Row는 문자열 인덱싱 대신 `row.year`, `row.id`로 접근.
- Hive ALTER LOCATION 및 MapReduce 조회에는 이름노드를 포함한 완전한 HDFS URI 사용.
- 구형 Hive CLI에서 문장 분리 문제가 생기는 속성 문자열 내부 세미콜론 제거.
